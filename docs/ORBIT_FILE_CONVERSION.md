
# Orbit File Conversion Guide

This document provides guidance for converting between different orbit file formats: TLE, OEM, OMM, and OPM. It covers conversion methods, metadata handling, available tools, and known limitations.

---

## Format Characteristics

### TLE
- **Fixed format**: 2-line ASCII with checksums
- **Implicit frame**: TEME of Date, Earth-centered, UTC
- **Mean elements**: SGP4 propagation model
- **No covariance**: No uncertainty information
- **No maneuvers**: Single epoch state only

### OPM (Orbit Parameter Message)
- **Osculating elements**: Instantaneous Keplerian state
- **Cartesian state**: Position and velocity vectors (mandatory)
- **Maneuver support**: Multiple maneuvers with delta-V
- **Covariance**: Optional 6×6 position/velocity covariance
- **Flexible frames**: Multiple reference frames supported

### OMM (Orbit Mean-Elements Message)
- **Mean elements**: Designed for TLE compatibility
- **Theory-specific**: Requires MEAN_ELEMENT_THEORY (SGP4, DSST, etc.)
- **TLE parameters**: Includes BSTAR, element set number, etc.
- **No maneuvers**: Not supported
- **Covariance**: Optional 6×6 position/velocity covariance

### OEM (Orbit Ephemeris Message)
- **Time series**: Multiple state vectors over time range
- **Cartesian only**: No Keplerian elements
- **Provenance matters**: Identical Cartesian state-vector fields can represent
	histories generated by mean-element propagation (SGP4, DSST, or Brouwer),
	osculating-element two-body propagation, numerical propagation, or external
	orbit determination. These histories are not model-neutral or interchangeable.
- **Interpretation metadata**: Record the originating propagator or orbit
	determination source, force and gravity models, integrator settings, frame,
	and time system alongside the OEM.
- **Interpolation**: Supports various interpolation methods
- **Covariance**: Optional position/velocity covariance matrices
- **Acceleration**: Optional acceleration data
- **No maneuvers**: State history only

## Format Selection Guide

| Use Case | Recommended Format |
|----------|-------------------|
| Space Surveillance Network data | TLE |
| High-precision orbit determination | OPM |
| Mean element propagation | OMM |
| Ephemeris time series | OEM |
| Maneuver planning | OPM |
| Uncertainty propagation | OPM or OMM (with covariance) |
| Legacy system compatibility | TLE |
| Interpolation between states | OEM |

## Conversion Reference

> **Do not treat OEM state histories as model-neutral.** Cartesian layout alone
> does not preserve whether a history came from SGP4, DSST, Brouwer, two-body
> Kepler propagation, numerical integration, or orbit determination. Account
> for provenance, frame, time system, and model-dependent error behavior before
> merging, comparing, fitting, or interpolating ephemerides.

### Provenance Record

An output requires an explicit provenance record whenever its file format does
not natively identify the model that generated its Cartesian states or fitted
elements. This always applies to generated OEMs and fitted OPMs. It also
applies to OMMs fitted from an OEM when the source history's origin is not
otherwise documented.

For CCSDS OEM, OMM, and OPM files, write portable `COMMENT` entries using this
form:

```text
COMMENT EPHEMERIS_PROVENANCE: source=<source format and model>; transformation=<operation>; target_model=<propagator or fit theory>
COMMENT EPHEMERIS_FIT: span=<duration>; samples=<count>; position_rms=<value>; velocity_rms=<value>
```

Include the source frame and time system, target gravity and force models,
integrator and step-size settings, user-supplied physical parameters, and maximum residuals
where applicable. An OPM may additionally use `USER_DEFINED_EPHEMERIS_*` keys
for structured values, but must retain the portable comments. A TLE has no
space for arbitrary provenance; write the same information to a companion
`--fit-report` file or preserve it in the preceding OMM/OEM.

### Propagator-Matched Arc Fitting

When a source ephemeris must be used by a different propagation model, generate
a Cartesian reference arc with the source model and optimize the target
propagator's initial Cartesian state against that arc. The fitted state is an
initial condition for the target model, not a lossless conversion of the source
elements. Define and record the fit span, sample times, position/velocity
weights, target force and gravity models, integrator settings, fitted physical
parameters, and position/velocity residual statistics.

For example, an SGP4 TLE or OMM can generate a reference arc that is fitted by
a numerical propagator. The resulting OPM contains a Cartesian initial state
for that numerical model; optional Keplerian elements derived from it are
osculating elements, not SGP4 mean elements. A fit is valid only for its stated
arc and may diverge outside that span.

This is a proposed capability; the current tools do not implement a
numerical-propagator initial-state optimizer.

`--fit-model` selects the orbital or propagation model that defines the fitted
output: `brouwer`, `dsst`, or `sgp4` for a mean-element OMM; `two-body` or
`numerical` for an OPM initial-state fit. Reserve `--fit-method` for a future
optimizer-algorithm choice, such as `gauss-newton` or
`levenberg-marquardt`. Derive OMM `MEAN_ELEMENT_THEORY` from `--fit-model`; do
not expose a free `--theory` override. During migration, retain `--mode` as a
deprecated alias for `--fit-model`, map `--mode tle` to `--fit-model sgp4`,
and reject `--theory` when it disagrees with the derived theory. Avoid generic
`--fit` and `--propagator`, because neither identifies whether it describes
input data or the target transformation.

The numerical-fit commands should reuse the force-model options of
`propagate-orbit`, including `--earth-gravity`, `--drag`, `--drag-coeff`,
`--drag-area`, `--srp`, `--srp-coeff`, `--integrator`, and
`--integrator-step-size`. They should require user-supplied physical parameters
when the corresponding force is enabled, never vary those parameters during
fitting, and reject a request that supplies fewer than two reference states.

### To OEM (Orbit Ephemeris Message)

#### OMM -> OEM
> ⚠️ **Accuracy**: SGP4 errors grow with propagation time; DSST is more accurate for long arcs.

**Conversion Method**:
- **SGP4**: `propagate-omm` produces an SGP4-generated Cartesian OEM
	(automatic based on `MEAN_ELEMENT_THEORY=SGP4`)
- **DSST**: `propagate-omm` produces a DSST-generated Cartesian OEM
	(automatic based on `MEAN_ELEMENT_THEORY=DSST`)

**Ephemeris-model handling**: Select a propagator that implements the OMM's
`MEAN_ELEMENT_THEORY`; SGP4, DSST, Brouwer-Lyddane, and other mean-element
theories require separate implementations. The resulting Cartesian OEM must
retain the selected theory as provenance and cannot be substituted for an OEM
generated by a different theory.

**Required provenance record**: State the source OMM theory, selected
propagator, output frame, and time system. A numerical alternative must also
state its force model, integrator settings, fit span, and residuals.

**Alternative numerical path**: Generate a reference OEM with the selected
mean-element propagator, fit a numerical propagator's Cartesian initial state
to that arc, then generate a separate numerically propagated OEM. This bridges
the OMM to a specific numerical force model; it does not make the two OEM
histories interchangeable.

**Options**: `--duration DURATION`, `--step SECONDS`

**Metadata**:
- **Preserved**: `OBJECT_NAME`, `OBJECT_ID`, `CENTER_NAME`, `REF_FRAME`, `TIME_SYSTEM`
- **Lost**: `MEAN_ELEMENT_THEORY`, `MEAN_MOTION`, `ECCENTRICITY`, `INCLINATION`, `RA_OF_ASC_NODE`, `ARG_OF_PERICENTER`, `MEAN_ANOMALY`, `BSTAR`/`BTERM`, `NORAD_CAT_ID`, `ELEMENT_SET_NO`, `REV_AT_EPOCH`, `MASS`, `SOLAR_RAD_AREA`, `DRAG_AREA`

#### OPM -> OEM
> ⚠️ **Accuracy**: Kepler (two-body) ignores all perturbations; errors grow rapidly for LEO. Use `propagate-orbit` for higher fidelity.

**Conversion Method**:
- **Kepler (two-body)**: `propagate-kepler` produces an osculating-
	Keplerian-generated Cartesian OEM with `-d/--duration` and `-s/--step`
- **Numerical (with perturbations)**: `propagate-orbit` produces a
	force-model-dependent numerically generated Cartesian OEM with `--duration`

**Ephemeris-model handling**: These are distinct conversion paths. The
two-body path starts from the OPM's osculating Keplerian elements, while the
numerical path starts from its Cartesian state and depends on the configured
force, gravity, and integrator models. Record the chosen path and numerical
configuration as OEM provenance.

**Required provenance record**: State `target_model=two-body-kepler` or
`target_model=numerical`, the input OPM epoch/frame/time system, and, for
numerical output, force/gravity models and integrator settings.

**Options**: `--duration DURATION`, `--step SECONDS`

#### TLE -> OEM
> ⚠️ **Accuracy**: SGP4 is a simplified model; errors grow with propagation time (km-level after days for LEO).

**Conversion Method**:
- **SGP4**: `propagate-tle` produces an SGP4-generated Cartesian OEM with
	`--duration` and `--step`
- **Via OMM**: `tle-to-omm` -> `propagate-omm` produces an SGP4-generated
	Cartesian OEM (uses `MEAN_ELEMENT_THEORY` from OMM)

**Ephemeris-model handling**: A TLE always requires SGP4 propagation. The
output is an SGP4-generated Cartesian OEM, not an osculating-Keplerian or
numerically propagated history, even though all outputs use the same
position/velocity layout.

**Required provenance record**: State `source=TLE; target_model=SGP4`, the
TLE epoch, TEME frame, and UTC time system. A numerical alternative must also
identify the SGP4 reference arc and fitted numerical model.

**Alternative numerical path**: Use the SGP4 OEM as a reference arc to fit a
numerical propagator, then produce a separate numerically propagated OEM. The
fit provides a model-specific approximation over its stated fit span.

**Options**: `--duration DURATION`, `--step SECONDS`

**Metadata**:
- **Preserved**: `OBJECT_NAME`, `OBJECT_ID` (from NORAD ID), `CENTER_NAME` (EARTH), `REF_FRAME` (TEME), `TIME_SYSTEM` (UTC)
- **Lost**: All TLE-specific parameters, mean elements, `BSTAR`, `ELEMENT_SET_NO`

### To OMM (Orbit Mean-Elements Message)

#### OEM -> OMM
> ⚠️ **Accuracy**: Fit quality depends on arc length and theory; short arcs or noisy data reduce accuracy.

**Conversion Method**:
- **SGP4 fitting**: `oem-to-omm --mode tle` with optional `--fit-span`
- **Brouwer-Lyddane fitting**: `oem-to-omm --mode brouwer` with optional `--fit-span`

**Ephemeris-model handling**: Choose the target mean-element theory before
fitting. SGP4-compatible TLE fitting, Brouwer-Lyddane fitting, DSST fitting,
and other theories require different fit models; one theory's fitted elements
cannot be relabeled as another's. Record the source OEM provenance because it
affects fit quality and interpretation.

**Required provenance record**: State the source OEM origin when known, target
mean-element theory, fit span, and residuals. `MEAN_ELEMENT_THEORY` alone does
not identify the source Cartesian arc.

**Current options**: `--mode {brouwer|dsst|tle}`, `--theory THEORY`,
`--fit-span DURATION`

**Proposed options**: `--fit-model {brouwer|dsst|sgp4}`, `--fit-span DURATION`,
`--source-model MODEL`, `--source-report PATH`, `--fit-report PATH`

#### OPM -> OMM
> ⚠️ **Accuracy**: Multi-step process introduces compounded errors; propagation + fitting both approximate.

**Conversion Method**:
- **Via OEM (two-body)**: `propagate-kepler` -> `oem-to-omm`
- **Via OEM (numerical)**: `propagate-orbit` -> `oem-to-omm`

**Ephemeris-model handling**: Select the intermediate OEM generation path
(two-body osculating Keplerian or numerical force-model propagation), then
select the target mean-element fitting theory. Both choices affect the result;
this is not a universal osculating-to-mean conversion.

**Required provenance record**: State the intermediate two-body or numerical
model, target mean-element theory, and propagation and fitting settings with
their residuals.

#### TLE -> OMM
**Conversion Method**:
- **Direct conversion**: `tle-to-omm`

**Ephemeris-model handling**: This is a direct field mapping because both
formats contain SGP4-compatible mean elements. The resulting OMM must declare
the SGP4 theory; it does not create DSST, Brouwer-Lyddane, or osculating
Keplerian elements.

**Provenance record**: No additional record is required for a lossless direct
mapping. Add one when the input TLE was generated or fitted from another source.

**Metadata**:
- **Preserved**: `NORAD_CAT_ID`, `CLASSIFICATION_TYPE`, `EPOCH`, `MEAN_MOTION`, `ECCENTRICITY`, `INCLINATION`, `RA_OF_ASC_NODE`, `ARG_OF_PERICENTER`, `MEAN_ANOMALY`, `BSTAR`, `ELEMENT_SET_NO`, `REV_AT_EPOCH`, `MEAN_MOTION_DOT`, `MEAN_MOTION_DDOT`, `OBJECT_NAME` (3-line TLE only)

### To OPM (Orbit Parameter Message)

#### OEM -> OPM
> ⚠️ **Accuracy**: Two-body Keplerian fit; ignores perturbations. Fitted elements are approximate, not true osculating elements.

**Conversion Method**:
- **Osculating Keplerian fit**: `oem-to-opm` — fits a two-body Keplerian orbit to the OEM arc; output preserves the first Cartesian state and includes fitted Keplerian elements at that epoch

**Ephemeris-model handling**: The output Keplerian elements are a two-body
approximation fitted to the source Cartesian history. For an OEM generated by
a mean-element theory or numerical force model, they are not automatically
source-model-consistent osculating elements; recovering those may require
theory-specific short-period reconstruction.

**Required provenance record**: State the source OEM origin when known and
whether output elements are a two-body fit, theory-specific reconstruction, or
derived from a numerical arc-fit state. Include numerical fit settings and
residuals when applicable.

**Alternative numerical fit**: Instead of producing a two-body OPM, fit the
target numerical propagator's Cartesian initial state to the OEM arc. This is
useful for external or orbit-determination OEMs and for OEMs generated by SGP4
or another mean-element theory when subsequent work requires numerical
propagation.

#### OMM -> OPM
> ⚠️ **Accuracy**: Multi-step; SGP4 propagation errors compound with two-body Keplerian fitting errors.

**Conversion Method**:
- **Via OEM**: `propagate-omm` -> `oem-to-opm`

**Ephemeris-model handling**: First propagate with the OMM's declared
mean-element theory, then fit an approximate two-body osculating state to the
resulting Cartesian OEM. The OPM's fitted elements are not interchangeable
with the OMM's mean elements and retain the propagation-and-fit provenance.

**Required provenance record**: State `source=OMM`, its mean-element theory,
the intermediate propagation model, and whether elements are a two-body
approximation or derive from a numerical fit; include fit settings and residuals.

**Alternative numerical fit**: Generate a Cartesian reference arc with the
OMM's declared mean-element theory and fit the initial state of the intended
numerical propagator. This produces an OPM for numerical propagation and must
record the source theory, target force model, fit span, and residuals.

#### TLE -> OPM
> ⚠️ **Accuracy**: Multi-step; SGP4/J2-only errors compound with two-body Keplerian fitting errors.

**Conversion Method**:
- **Via OMM**: `tle-to-omm` -> `propagate-omm` -> `oem-to-opm`
- **Via OEM**: `propagate-tle` -> `oem-to-opm`

**Ephemeris-model handling**: Both paths first create an SGP4-generated
Cartesian history, then fit approximate two-body osculating Keplerian
elements. The final OPM is not a direct representation of the TLE's SGP4 mean
elements.

**Required provenance record**: State `source=TLE; reference_model=SGP4` and
identify the intermediate propagation or fitted numerical model. Include the
reference span, fit settings, and residuals.

**Alternative numerical fit**: Propagate the TLE with SGP4 to create a
reference Cartesian arc, then optimize the initial Cartesian state of the
numerical propagator intended to consume the OPM. Store the fitted state in the
OPM and derive any optional Keplerian fields as osculating elements. Report the
fit span and residuals; the result cannot reproduce SGP4 exactly or guarantee

### To TLE (Two-Line Element Set)

#### OEM -> TLE
> ⚠️ **Accuracy**: Orbit fitting introduces approximation errors; TLE format has limited precision (fixed-width fields).

**Conversion Method**: Orbit fitting + direct conversion
- Requires orbit fitting to mean elements + TLE formatting
- Multi-step process (OEM -> OMM -> TLE)
- **Tool**: `oem-to-tle` with the existing `--fit-span` and
	`--tle-refinement` options

**Ephemeris-model handling**: The fit must specifically produce
SGP4-compatible mean elements. OEM provenance affects the fit, but an OEM
from any source is converted to a new SGP4 model rather than preserving its
original mean-element, osculating, or numerical propagation model.

**Required provenance record**: A TLE cannot carry the source OEM provenance.
Put the source model, SGP4 fit configuration, and residuals in the companion
fit report and, where possible, the intermediate OMM comments.

#### OMM -> TLE
**Conversion Method**:
- **Direct conversion**: `omm-to-tle`
- **Composed refit**: `propagate-omm` → OEM → `oem-to-tle`

For a non-SGP4 OMM, generate a Cartesian reference arc first, then fit that
OEM to SGP4-compatible mean elements:

```text
PYTHONPATH=src python -m ephem_toolkit.propagate_omm input.omm \
  --duration 2h --step 5m --output reference.oem
PYTHONPATH=src python -m ephem_toolkit.oem_to_tle reference.oem \
  --fit-span 2h --fit-report output.fit.json --output output.tle
```

The intermediate OEM is the reference history for the fit. The resulting TLE
is valid for the fitted arc and is not a lossless conversion of the source
OMM's theory.

**Ephemeris-model handling**: Direct conversion is valid only for an OMM with
SGP4-compatible mean elements and the required TLE parameters. Reject or
explicitly re-fit DSST, Brouwer-Lyddane, and other non-SGP4 OMMs before
producing a TLE.

**Provenance record**: No additional record is required for a direct
SGP4-compatible mapping. For a non-SGP4 refit, put the source OMM theory, fit
settings, and residuals in the OEM/TLE fit report produced by the composed
workflow.

#### OPM -> TLE
> ⚠️ **Accuracy**: Multi-step; propagation + orbit fitting errors compound; TLE format has limited precision.

**Conversion Method**:
- **Multi-step (two-body)**: `propagate-kepler` -> `oem-to-omm --mode tle` -> `omm-to-tle`
- **Multi-step (numerical)**: `propagate-orbit` -> `oem-to-omm --mode tle` -> `omm-to-tle`

**Ephemeris-model handling**: Select the intermediate two-body or numerical
OEM propagation path, then fit SGP4-compatible mean elements before writing
the TLE. The final TLE is a new SGP4 model; it is not interchangeable with the
intermediate osculating or numerically generated Cartesian history.

**Required provenance record**: A TLE cannot preserve the OPM propagation
path. Put the selected path, SGP4 fit settings, and residuals in a companion
fit report.
